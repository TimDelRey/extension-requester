# Request Catcher

Расширение Chrome для ручной подмены исходящего HTTP(S) запроса **до отправки**. Работает локально: без сервера-посредника, аккаунта, внешних библиотек и сборки.

## Установка

1. Откройте `chrome://extensions` в Chrome 125 или новее.
2. Включите **Режим разработчика**.
3. Нажмите **Загрузить распакованное расширение** и выберите папку `request-catcher`, в которой лежит `manifest.json`.
4. Закрепите Request Catcher через меню расширений и нажмите его иконку. Откроется боковая панель.

Если используете ZIP из `dist/request-catcher.zip`, сначала распакуйте его и выберите вложенную папку `request-catcher`.

## Использование

1. Откройте нужный сайт и панель расширения.
2. Оставьте настройки по умолчанию: «Ближайший запрос (рекомендуется)» и «Все (включая переходы)». Так ловятся API-запросы, отправки форм и обычные переходы.
3. При необходимости укажите часть URL, например `/api/orders`, чтобы отсеять аналитику.
4. Нажмите **Включить перехват**, дождитесь статуса **ОЖИДАЮ ЗАПРОС** и выполните действие на сайте. Первый подходящий запрос задержится перед отправкой, и панель откроет редактор. По умолчанию на действие есть 30 секунд; время редактирования этим таймером не ограничено.
5. Измените метод, полный URL (включая query string) или заголовки. Заголовки задаются строками `Name: value`; удаление строки удаляет заголовок из набора подмены.
6. Для изменения тела откройте «Тело» и включите **Заменить тело целиком**. Доступны текст UTF-8 и Base64. Для JSON сохраните `Content-Type: application/json`.
7. Нажмите **Отправить с изменениями**, **Отправить исходный** или **Отменить запрос**. Ответ получит исходная страница.

Режим «Ближайший запрос» работает независимо от DOM-события: в том числе для действий по `pointerdown`, раннему обработчику сайта или таймеру. Режим «После следующего клика» доступен отдельно для отсечения запросов до клика. Для просмотра только API выберите «Только Fetch/XHR».

## Если переход раньше происходил без редактора

В версии 1.0.1 по умолчанию стояли Fetch/XHR после события `click`: обычная навигация не подходила под фильтр, а переход по `pointerdown` мог начаться раньше. В версии 1.0.2 по умолчанию ловятся все HTTP(S)-запросы сразу после включения. После обновления расширения закройте и снова откройте его панель.

Для перехода по ссылке обычно задержится **GET без тела**. Его данные меняются в полном URL (например, `?id=123`) и во вкладке «Заголовки». Для POST/PATCH откройте «Тело», включите «Заменить тело целиком» и исправьте JSON или данные формы. «Отправить исходный» продолжит запрос без подмены, «Отправить с изменениями» — с правками.

Если сайт меняет только адрес через `history.pushState` или `#` без сетевого запроса, HTTP-запроса для остановки нет. В таком случае перехватывайте запрос API, который загружает или сохраняет данные. Переходы в новой вкладке текущая версия не перехватывает.

URL редактируется только в рамках исходного **origin**: схема, хост и порт должны совпадать. Это предотвращает случайный перенос Cookie, Authorization и других токенов на другой сайт, включая понижение HTTPS до HTTP. Ожидание клика автоматически выключается через 60 секунд. Переход самой страницы на другой origin завершает сессию перехвата.

## Проверка на локальном примере

Команды проверки и демо доступны в исходном проекте; установочный ZIP содержит файлы расширения и документацию. Нужен Node.js 22+:

```sh
npm run demo
```

Откройте `http://127.0.0.1:8787`, включите перехват и нажмите «Отправить JSON». Измените URL на `/echo?source=edited` (сохранив полный адрес), добавьте `X-Test: hello`, включите замену тела и поменяйте JSON. После продолжения страница покажет фактически полученные сервером данные. Есть также XHR, URL-encoded форма, multipart с бинарным файлом, навигация и редирект 302, запускаемый по `pointerdown`.

## Как работает

Manifest V3, `chrome.debugger` и Chrome DevTools Protocol `Fetch.requestPaused` / `Fetch.continueRequest`. Перед отправкой запрос остаётся в Chrome; расширение не пересоздаёт его через `fetch`. Это сохраняет контекст страницы и получение ответа её кодом. Событие клика отслеживается в изолированном JS-контексте через CDP binding. Подключаются также iframe и связанные dedicated workers, доступные через auto-attach.

Разрешения: `debugger` для задержки и изменения запросов, `sidePanel` для редактора, `activeTab` для сведений о выбранной вкладке. Постоянный доступ к сайтам через `host_permissions` не запрашивается. Тело и заголовки не записываются в storage, не отправляются сторонним сервисам и очищаются из редактора после завершения. Переключение вкладки сохраняет черновик только в памяти открытой панели.

Явная CSP запрещает сетевые подключения из интерфейса и service worker расширения, удалённые ресурсы, iframe и встроенные скрипты. Это не мешает продолжению исходного запроса через CDP. Управление принимается только от собственной страницы панели; данные и команды сессии доступны её владельцу. Если Chrome не подтвердил отмену выбранного запроса, расширение сохраняет перехват и предлагает повторить отмену. При закрывшейся панели такую сессию можно восстановить, вновь открыв панель на этой вкладке. При ошибке отключения отладчика статус остаётся видимым и можно повторить выключение.

В версии 1.0.3 сохранены ограничения безопасности версии 1.0.1–1.0.2; панель переработана для меньшего количества текста на экране (подробности скрыты в «Что нужно знать»), а закрытие вкладки с активным перехватом теперь всегда проходит через штатную остановку (отмена запроса, снятие инъекций, отключение отладчика), а не только через прямое удаление сессии. Проверка: 29 модульных тестов и 10 сценариев в Chrome, включая задержку навигации по `pointerdown`, редактирование перед отправкой и последующий редирект 302 на другой origin.

## Ограничения

- Chrome показывает штатное уведомление об отладке. DevTools или другое расширение-отладчик могут конфликтовать с подключением. Не отключайте отладчик через уведомление, пока запрос задержан: судьбой такого запроса уже управляет Chrome.
- Служебные страницы, Chrome Web Store и запрещённые политиками браузера страницы недоступны.
- Ловится **первый подходящий запрос в течение 3, 10 или 30 секунд**, а не доказанная причинно-следственная связь. Фоновые запросы могут попасть первыми: используйте URL-фильтр. В отдельном режиме после клика сайт с более ранним обработчиком на `window` или запросом по `pointerdown` может отправить запрос до события `click`; для таких случаев используйте режим ближайшего запроса.
- Перехватывается один запрос за цикл. Остальные проходят. Автоматические CORS-запросы OPTIONS пропускаются. Для следующего запроса включите перехват заново.
- CORS, CSP и проверки сервера продолжают действовать. Продолжение в Chrome не означает, что сервер принял запрос. Изменение URL не обновляет адресную строку. Один цикл задерживает один запрос; после продолжения сервер может вернуть 302, а последующие шаги редиректа проходят без повторной остановки.
- В редакторе показываются заголовки, доступные через Chrome на момент паузы. Host, Content-Length, Connection и Transfer-Encoding формирует браузер; при подмене они исключаются из ручного набора. Некоторые другие заголовки также может ограничивать браузер. Cookie относится к текущему шагу запроса; это не редактор cookie-хранилища.
- Если тело не заменять, исходные байты и файлы остаются у Chrome. Предпросмотр и новое тело ограничены 1 МиБ, заголовки редактора — 128 КиБ, URL — 16 КиБ. Пропущенное Chrome тело неизвестного размера дополнительно не запрашивается. В текстовом представлении multipart файлы могут отсутствовать. Замена означает полную замену: для multipart самостоятельно сохраняйте boundary и все части; для бинарных данных используйте Base64.
- Не перехватываются сообщения уже открытого WebSocket, запросы новой вкладки и данные, которые Service Worker возвращает без сети. Поддержка отдельных worker-запросов зависит от целевого процесса Chrome.
- Задержка может привести к таймауту или отмене запроса самой страницей. Закрытие панели отменяет выбранный запрос и отключает перехват, если Chrome подтвердил эти операции. При ошибке отмены сессия сохраняется для восстановления. Закрытие вкладки, перезапуск или перезагрузка расширения прерывают сессию; Chrome управляет незавершёнными запросами. Расширение не может гарантировать отмену при принудительном отключении отладчика средствами браузера.

## Разработка

```sh
npm test                 # Валидация, байты тела, жизненный цикл перехвата
npm run test:browser     # Реальный Chrome, отдельный временный профиль, локальный сервер
npm run pack             # dist/request-catcher.zip, без файлов разработки
```

Browser-тест использует установленный Chrome и CDP `Extensions.loadUnpacked` с флагом `--enable-unsafe-extension-debugging`. Путь можно задать через `CHROME_PATH`. Пользовательский профиль Chrome не используется.

Документация: [chrome.debugger](https://developer.chrome.com/docs/extensions/reference/api/debugger), [Fetch CDP](https://chromedevtools.github.io/devtools-protocol/tot/Fetch/), [Side Panel](https://developer.chrome.com/docs/extensions/reference/api/sidePanel).
